================================================================================
                            CORE CONCEPTS MATRIX
================================================================================

INTERMEDIATE OPERATIONS (Return Stream - Chainable):
┌─────────────────────────────────────────────────────────┐
│ filter(Predicate<T>)          → Select matching elements
│ map(Function<T, R>)           → Transform each element
│ flatMap(Function<T, Stream>)  → Map and flatten nested
│ distinct()                    → Remove duplicates
│ sorted()                      → Order by natural order
│ sorted(Comparator<T>)         → Order by custom comparator
│ limit(long n)                 → Limit to first n elements
│ skip(long n)                  → Skip first n elements
│ peek(Consumer<T>)             → Debug/inspect elements
└─────────────────────────────────────────────────────────┘

TERMINAL OPERATIONS (Produce Result - Ends Stream):
┌─────────────────────────────────────────────────────────┐
│ forEach(Consumer<T>)          → Process each element
│ collect(Collector<T,A,R>)     → Gather into collection
│ reduce(BinaryOperator<T>)     → Aggregate to single value
│ reduce(T, BinaryOperator<T>)  → With identity element
│ count()                        → Count elements
│ findFirst()                    → Get first (Optional)
│ findAny()                      → Get any (Optional)
│ anyMatch(Predicate<T>)         → Any element matches?
│ allMatch(Predicate<T>)         → All elements match?
│ noneMatch(Predicate<T>)        → No elements match?
│ min(Comparator<T>)             → Find minimum
│ max(Comparator<T>)             → Find maximum
└─────────────────────────────────────────────────────────┘

COLLECTORS (Specialized Terminal Operations):
┌─────────────────────────────────────────────────────────┐
│ toList()                      → Collect to List
│ toSet()                       → Collect to Set
│ toMap(keyMapper, valueMapper) → Collect to Map
│ joining()                     → Concatenate strings
│ joining(delimiter)            → With delimiter
│ summingInt/Double/Long()      → Sum values
│ averagingInt/Double/Long()    → Average values
│ summarizingInt/Double/Long()  → Full statistics
│ groupingBy(classifier)        → Group by key
│ groupingBy(classifier, downstream)
│ partitioningBy(predicate)     → Partition T/F
│ mapping(mapper, collector)    → Transform before collect
│ maxBy(comparator)             → Find maximum
│ minBy(comparator)             → Find minimum
│ toCollection(supplier)        → Collect to custom type
└─────────────────────────────────────────────────────────┘

STREAM TYPES:
┌─────────────────────────────────────────────────────────┐
│ Stream<T>                     → Generic stream
│ IntStream                     → Primitive int stream
│ LongStream                    → Primitive long stream
│ DoubleStream                  → Primitive double stream
│ Optional<T>                   → Container for nullable value
└─────────────────────────────────────────────────────────┘

================================================================================
                          KEY ADVANTAGES OF STREAMS
================================================================================

✓ Declarative: Express WHAT, not HOW
✓ Chainable: Combine operations fluently
✓ Lazy: Operations execute only when needed
✓ Parallel: Easy parallel processing
✓ Functional: Use lambdas and method references
✓ Type-safe: Compile-time type checking
✓ Immutable: Doesn't modify source
✓ Readable: More expressive than loops

================================================================================
                          PERFORMANCE CONSIDERATIONS
================================================================================

When to use Streams:
  ✓ Complex data transformations
  ✓ Multiple filtering/mapping operations
  ✓ Code clarity is important
  ✓ Working with large datasets
  ✓ Parallel processing needed

When NOT to use Streams:
  ✗ Simple single operations
  ✗ Performance-critical paths on small data
  ✗ Need to modify source collection
  ✗ Debugging complex chains

Parallel Streams:
  • Use for datasets > 10,000 items
  • Thread overhead offsets benefits for small data
  • Use with stateless operations
  • Avoid I/O operations

================================================================================
                        COMMON PATTERNS DEMONSTRATED
================================================================================

1. FILTER-MAP-REDUCE
   data.stream()
     .filter(condition)
     .map(transformation)
     .reduce(aggregation)

2. GROUP AND AGGREGATE
   data.stream()
     .collect(Collectors.groupingBy(key, Collectors.summingInt(value)))

3. FIND WITH OPTIONAL
   data.stream()
     .filter(condition)
     .findFirst()
     .ifPresentOrElse(found::println, () -> System.out.println("Not found"))

4. TRANSFORM AND COLLECT
   data.stream()
     .map(mapper)
     .collect(Collectors.toList())

5. VERIFY CONDITIONS
   data.stream().anyMatch(condition)
   data.stream().allMatch(condition)
   data.stream().noneMatch(condition)

6. PARTITION
   data.stream()
     .collect(Collectors.partitioningBy(predicate))

7. SORT AND LIMIT
   data.stream()
     .sorted(comparator)
     .limit(n)

8. STATISTICS
   data.stream()
     .mapToInt(mapper)
     .summaryStatistics()
