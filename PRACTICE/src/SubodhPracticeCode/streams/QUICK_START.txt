⚡ KEY OPERATIONS

FILTERING & SELECTING:
  .filter(predicate)          Select matching elements
  .distinct()                 Remove duplicates
  .limit(n)                   Take first n elements
  .skip(n)                    Skip first n elements

TRANSFORMING:
  .map(function)              Transform each element
  .flatMap(function)          Map and flatten nested

COLLECTING:
  .collect(toList())          Gather to List
  .collect(toSet())           Gather to Set
  .collect(groupingBy(key))   Group by key
  .collect(partitioningBy())  Partition true/false

AGGREGATING:
  .reduce(function)           Combine all elements
  .count()                    Count elements
  .max(comparator)            Find maximum
  .min(comparator)            Find minimum

CHECKING:
  .anyMatch(predicate)        Any element matches?
  .allMatch(predicate)        All elements match?
  .noneMatch(predicate)       No elements match?

FINDING:
  .findFirst()                Get first (Optional)
  .findAny()                  Get any (Optional)

EXECUTING:
  .forEach(action)            Process each element
  .sorted(comparator)         Sort elements
  .peek(action)               Debug/inspect

💡 COMMON PATTERNS

FILTER-MAP-REDUCE:
  data.stream()
    .filter(condition)
    .map(transformation)
    .reduce(aggregation)

GROUP AND AGGREGATE:
  data.stream()
    .collect(Collectors.groupingBy(key, Collectors.summingInt(value)))

FIND WITH OPTIONAL:
  data.stream()
    .filter(condition)
    .findFirst()
    .ifPresentOrElse(System.out::println, () -> {})

TRANSFORM AND COLLECT:
  data.stream()
    .map(mapper)
    .collect(Collectors.toList())

SORT AND LIMIT:
  data.stream()
    .sorted(comparator)
    .limit(n)

STATISTICS:
  data.stream()
    .mapToInt(mapper)
    .summaryStatistics()

📌 REMEMBER

• Streams are lazy - operations don't execute until terminal operation
• Use streams for complex transformations, not simple loops
• Parallel streams work best with large datasets (10,000+ items)
• Always handle Optional values properly
• Use peek() for debugging, not in production
• Method chaining makes code more readable
